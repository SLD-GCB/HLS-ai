# 鸿胪寺

> 一个**本地优先**的 AI 桌面应用：既能当角色扮演聊天（接在线 API 也可以），
> 也能当编程助手（让模型读代码、改代码、跑命令）。
>
> **开箱即用，不装任何东西。** 整个文件夹拷走就能跑 —— 不用装 Python、
> 不用 `pip install`、不用装 CUDA 工具包。
> 想在自己的显卡上跑本地模型，软件里**自带一整套编译工具链**，
> 点几下就能给你的卡编一份。

---

## 项目介绍

### 它是怎么来的

市面上的 AI 客户端大致分两类：一类是**云端的**，聊什么都得先上传；
一类是**本地跑的**，但装起来本身就是一道门槛 —— Python 环境、CUDA 工具包、
编译工具链，随便哪一步就能卡住一整天。

这个项目想做的是第三种：**东西全在本机，但你不需要装任何东西。**

- 模型跑在你自己的机器上，聊天内容、角色卡、记忆，全都留在硬盘上那一个文件夹里；
- 整个软件是一个包，解压双击就能用；
- 连"换张显卡就得重新编译一遍框架"这件事，也塞进软件里了 ——
  **包里自带一整套编译工具链**，点几下就能给你那张卡编一份，
  不用装 Visual Studio，也不用装 CUDA 工具包。

### 它有什么不一样的

| | |
|---|---|
| **自带编译器** | 软件里带了一整套精简的 **MSVC + Windows SDK + CUDA + Vulkan SDK**。别的程序告诉你"请自行编译"，这个程序**自己就能编** |
| **N 卡 A 卡都能吃** | 编译框有**两种挡位**：**NVIDIA**（走 CUDA）和 **AMD**（走 Vulkan，Intel / 核显也能用）。包里另带一份 **CPU 兜底**，没显卡的机器照样跑 |
| **完全离线可跑** | 模型下好之后，从聊天到编程助手，全程不联网 |
| **上下文透明** | 专门有一页给你看"这一次到底会发给模型什么"——哪条被截了、为什么被截，一目了然，能删能调 |
| **记忆可控** | 长期记忆既能自己手写条目，也能让程序自动回收；全都是一行一行能读能改的 JSON |
| **动手前先问** | 编程助手要改你的文件、跑命令之前，会**停下来等你点**「允许」或「拒绝」 |
| **不装糊涂** | 出了问题宁可当场报错，也不"看起来能用、其实悄悄退化"。所以你会看到很多明确的中文警告 —— 那都是故意的 |

### 名字

「鸿胪寺」是古代掌管朝会礼仪、接待四方宾客的官署。
软件取这个名字，也是这个意思 —— 招待你自己请来的各方模型。

### 适合谁

**适合**：想让模型在自己机器上跑的人、喜欢捏角色写设定的人、
想让模型帮忙改代码但不想把代码传出去的人、以及**受够了配环境**的人。

**不适合**：想要手机 App 的、希望"点一下就全自动"的、
以及完全不熟悉电脑操作的人 —— 下模型和调参数这两步，还是得自己动动手。

### 技术栈

Python + PySide6（Qt）+ llama.cpp。本地推理走 `llama-cpp-python`，界面是 Qt，
数据全是本机 JSON 文件 —— **没有数据库、没有后台服务、没有账号体系。**

关于联网，说得准确一点：

- **用本地模型的时候，它全程不联网**（下完模型之后，聊天和编程助手都不需要网络）；
- **你自己配了在线 API 之后**，那部分对话才会发给你指定的那个服务商 ——
  发给谁、什么时候发，都由你怎么配决定；
- 除此之外，**程序自己没有写任何"主动外发"的逻辑** —— 没有使用统计、没有数据回传、
  没有自动更新检查。

## 一、这个软件能干什么

| 能力 | 说明 |
|---|---|
| **角色扮演聊天** | 建角色卡（人设 / 开场白 / 示例对话），开多段会话，流式回复 |
| **接在线 API** | OpenAI 兼容（ollama / vLLM / DeepSeek…）、Anthropic、Google Gemini 都行 |
| **跑本地模型** | 直接从软件里下载 GGUF 模型，配一套 `local` 接口就能离线聊 |
| **编程助手** | 让本地模型读文件、改文件、跑命令，带**审批机制**（每一步动手前问你） |
| **上下文与长期记忆** | 能看到"这次到底会发给模型什么"，能删能调；长期记忆可手改，也能自动回收 |
| **自带模型框架编译器** | 显卡不被包里那份支持时，**用包里自带的工具链给自己编一份**，不用装 VS / CUDA / Vulkan SDK。**N 卡、A 卡两种挡位都行** |

**设计上的一条硬原则：不装糊涂。** 出问题尽量当场报出来，不搞"看起来能用、
其实悄悄退化"那一套。所以这个软件里有很多明确的中文报错和警告 —— 它们是故意的。

## 二、运行前提

| 前提 | 要求 |
|---|---|
| 系统 | **Windows 10 或更新，64 位**（不支持 32 位；不支持 Win 7 / 8） |
| Python | **不需要** —— 运行时已经打包进 exe |
| 依赖库 | **不需要装** —— 全在 `依赖库/` 里 |
| CUDA 工具包 | **不需要装** —— 运行时需要的 cublas 已经随包带上（约 492 MB） |
| Vulkan SDK | **不需要装** —— 只有"给 A 卡编框架"时才用得着，而那份工具链也在包里 |
| 显卡 | **不是必须的**。没显卡 / 显卡不被支持 → 自动用 CPU 版框架（慢，但一定能跑）。想用 GPU 见 [九](#九我的显卡能不能用-gpu) |
| 磁盘 | 至少留 5 GB（包本体 + 下载的模型） |
| 路径 | **路径带中文也没关系**（桌面、下载文件夹、中文用户名都可以） |

> ⚠ **只有一个硬规矩：整个文件夹一起拷。**
> `鸿胪寺.exe` 和 `依赖库/` **必须待在同一个目录里**，不能拆开、不能改名。
> 只拷 exe 是跑不起来的。

## 三、安装与启动

1. 把发布包**整个文件夹**解压到任意位置（中文路径也行）。
2. 双击 `鸿胪寺.exe`。
3. 主界面直接打开，**不会有黑色终端窗口**跟着弹出来。

**第一次打开建议走一遍这个顺序**：

```
接口 → 本地模型…        （下几个模型，或者跳过，先接在线 API）
接口 → 接口配置…        （建一套接口：在线 API 或者本地模型）
接口 → 模型框架配置…    （确认用哪套框架，默认「自动」就行）
```

## 四、目录结构

```
鸿胪寺.exe        主程序（Python 代码 + Python 运行时，全在里面）
依赖库/           第三方依赖（PySide6 / llama_cpp / numpy …）
酒馆数据/         你的全部数据（角色卡、会话、记忆、模型…）
编译环境/         一整套编译工具链（MSVC + Windows SDK + CUDA + Vulkan SDK），用来给你的显卡编模型框架
使用说明.txt      简版说明（跟本文件内容有重叠，放在包里方便直接看）
本文件            你正在看的这个
```

⚠ **别删 `编译环境/`**，除非你确定永远不需要自己编模型框架 ——
它是包里最大的那块，但也是"别人的显卡跑不了 GPU 时唯一的自救路"。

## 五、五分钟上手

### 路线 A：接在线 API（最快）

1. 菜单 **接口 → 接口配置…**（`Ctrl+I`）
2. 点 **新建一套**
3. **协议**选你要的（OpenAI 兼容 / Anthropic / Gemini）
4. 填 **地址** 和 **密钥**
5. **模型**那一格：按右边的 **发现模型** 自动拉一份清单，或者直接手打模型名
6. 点 **保存**
7. 回主界面，在中间聊天栏那个 **接口下拉** 里选中它 → 开始聊

### 路线 B：跑本地模型（完全离线）

1. 菜单 **接口 → 本地模型…**（`Ctrl+M`）
2. 右边选 **来源**（默认 modelscope，不用梯子）、挑一个模型、按 **开始下载**
3. 下完自动进 `酒馆数据/模型/`
4. 再回 **接口配置** 新建一套：**协议选 `local`**，模型那一格填刚下的 GGUF 文件名
5. 保存 → 聊天栏接口下拉里选中它 → 开始聊

## 七、功能详解

### 7.1 角色卡

**在哪**：左栏，或者菜单 **角色 → 新建角色**（`Ctrl+N`）。

**能填什么**

| 字段 | 说明 |
|---|---|
| 头像 | `选一张…` 挑本地图片（自动缩到 512 存成 PNG）；`去掉` 清掉 |
| 名字 | **必填**，空了保存会当场报错 |
| 简介 | 一句话介绍 |
| 标签 | 用来搜 / 筛选 |
| 人设 | 系统提示词的核心部分 |
| 开场白 | **新建会话时自动落成第一条消息** |
| 示例对话 | 给模型的示范 |

**操作**：`新建` / `编辑` / `删除`，列表里**双击 = 编辑**。

> ⚠ **删除角色会连带删掉**：头像、这个角色的所有会话、所有消息、
> 以及这个角色的长期记忆。**删之前想清楚。**

---

### 7.2 聊天

- **发送**：`Ctrl+Enter`（回车是换行，不是发送）
- **停止**：输入框旁边的 `停止` 按钮
- **气泡**：鼠标悬停会出现四个小按钮 ——

| 按钮 | 作用 |
|---|---|
| `复制` | 复制这条的内容 |
| `编辑` | 改这条（改完从这条往下重新生成） |
| `重说` | 让模型重答这一条（**覆盖原序号，不会长出重复行**） |
| `删` | 删掉这条 |

- **接口下拉**：在聊天栏中间。**它只影响当前这一段会话** —— 换一段会话就是另一套接口。
- **会话栏（右栏）**：`新对话`（角色有开场白就自动落第一条）、`删`。
  会话标题自动取第一句话的前 20 字，**你自己改过的不覆盖**。

---

### 7.3 上下文与长期记忆

**在哪**：菜单 **会话 → 上下文…**（`Ctrl+K`）。一个窗口两个页签。

#### 页签一：聊天会话

| 区域 | 能干什么 |
|---|---|
| 顶部 | 调 **上下文条数**、**字数上限**、**系统提示**，改完按 `保存设置` |
| 左列 | 消息清单，每条标着 `[发]`（发给模型的）/ `[系]`（系统）/ `[截]`（被截掉的）；可 `删掉这条`、`清空这段` |
| 右列 | **真实显示"这次实际会发出去的样子"** |
| 下方 | **长期记忆板**：`新增一条` / `保存这条` / `删掉这条`。勾选框一按即落盘 |

#### 页签二：编程助手

看某一次任务的完整转录，可以 `刷新`、`删掉这次任务`；记忆板绑的是**当前工作目录**。

> 💡 **长期记忆怎么用**：分成"手动条目"和"自动回收"两种。你手写的条目
> 会被塞进一个暗槽发给模型；自动回收的那些则按水位和指纹去重。
> 全部存在 `酒馆数据/记忆.json` 和 `酒馆数据/记忆/` 里，可以直接改。

---

### 7.4 接口配置（在线 API）

**在哪**：菜单 **接口 → 接口配置…**（`Ctrl+I`）。

**顶部「看哪一组」**：分成 **对话配置** 和 **agent 配置** 两组 ——
给编程助手调的温度不会把聊天带走。老数据（没有分组那一列）标着「旧配置」，
**两边都看得见、两边都能用**，改一下"给谁用"就归到一边了。

**表单字段**

| 字段 | 说明 |
|---|---|
| 名称 | 必填，存多套时全靠它认人 |
| 协议 | 见下表 |
| 地址 | 例如 `http://127.0.0.1:11434/v1` |
| 密钥 | **默认打码**，按住旁边的「看」才显示明文 |
| 模型 | 可编辑下拉：手打也行，按 **发现模型** 也能拉 |
| 温度 / 最大输出 | 采样参数 |
| 附加头 | JSON，给需要额外 HTTP 头的服务用 |
| 给谁用 | 对话 / agent |

**协议对照**

| 协议 | 用于 |
|---|---|
| `OpenAI 兼容` | ollama、vLLM、DeepSeek、以及绝大多数中转服务 |
| `Anthropic` | Claude |
| `Google Gemini` | Gemini |
| `local` | 本地 GGUF 模型（llama.cpp，不联网）—— **编程助手只认这一种** |

> ⚠ **密钥是明文存在 `酒馆数据/接口配置.json` 里的。** 就在程序旁边，
> 打得开就读得到。**别把 `酒馆数据/` 整个发出去。**
> 密钥框默认打码、要看得自己点，就是为了防"截图 / 录屏时泄露"。

> 💡 **「发现模型」不用先保存**：它会拿你**表单里现填的**协议 / 地址 / 密钥
> 去问一句 `GET {地址}/models`，把回来的模型名灌进下拉。
> `local` 协议下它数的是 `酒馆数据/模型/` 里的 GGUF 文件。

---

### 7.5 本地模型

**在哪**：菜单 **接口 → 本地模型…**（`Ctrl+M`）。

**左边**：已下载的模型清单 + `刷新` / `删除选中`，底下是**引擎状态**那一行。

**右边下载区**

| 控件 | 说明 |
|---|---|
| 来源 | **modelscope**（默认，不用梯子）/ hf-mirror.com / HuggingFace 官方（要梯子） |
| 挑选方式 | 精选清单 / 搜索仓库 / 自己填仓库 |
| 类别 | 通用 / agent / 聊天 —— 用来筛精选清单 |
| 文件 | 选中要下的那个 GGUF（不同量化 = 不同大小和效果） |
| 开始下载 / 取消 | 带进度条，**断点续传**：下到一半关了，下次自动接着下 |

> ⚠ **正在生成回复时，不给下载、也不给删模型。**
> ⚠ **「取消」是置了个旗**，真正的生效点是**这次下载回来之后** ——
> 点完可能还会再跑一小会儿。
> ⚠ **下到一半的文件不会被当成模型。** 程序会跳过半成品目录，
> 免得给你挪出一个大小看着挺大、其实加载不了的坏模型。

---

### 7.6 编程助手

**在哪**：菜单 **视图 → 编程助手**（`Ctrl+Shift+A`），会切到整屏的助手页。

**它做什么**：让模型读文件、列目录、找内容、写文件、改文件、跑命令。

**用之前**

| 前提 | 说明 |
|---|---|
| 接口 | **只能用 `local` 协议的接口**（本地模型）。云端接口这条链已经去掉了 |
| 工作目录 | 点 `工作目录…` / `换目录…` 选一个文件夹，助手只能在这个范围里动手 |
| 设置 | `设置…` 里调 **最大步数**、**上下文大小**、**单步输出上限** |

**界面元素**

- **转录卡片**：每一步做了什么，一张一张摞着显示
- **审批卡**：模型要动你的文件或跑命令时，**停下来问你**

```
[允许一次]   [本任务总是允许]   [拒绝]
```

- **用量条**：显示上下文用了多少、走到第几步
- `开始`（`Ctrl+Enter`）/ `停止` / `清空`

**几条必须知道的**

> ⚠ **审批超时 = 拒绝。** 审批卡晾着不管（默认 5 分钟）会被当成"拒绝"，
> 任务继续往下走。**别开着审批卡去干别的。**
>
> ⚠ **提示太长会从前面截。** 超过模型的上下文上限时，程序**从最前面开始截**，
> 也就是**最先丢的是系统提示**。所以：
> 折叠完仍然超限 → 任务直接中止，而不是硬发一个残缺的提示。
>
> ⚠ **`Ctrl+Enter` 才是开始**，回车是换行。

---

### 7.7 模型框架配置

**在哪**：菜单 **接口 → 模型框架配置…**（`Ctrl+G`）。

**它解决什么**：包里的 `依赖库/llama_cpp/` 下**有两套框架**：

```
lib/        当前这套「GPU 版」——**CUDA 版或 Vulkan 版**，看你自己编了哪一份
lib_cpu/    CPU 版（不碰任何 CUDA / Vulkan 东西，慢，但什么机器上都跑得起来）
```

⚠ `lib/` 里**同时只会有一套**。编哪一挡就换成哪一套（旧的自动留作备份）——
所以那个框里会明说"现在这套：CUDA 版"还是"Vulkan 版"。

用哪套，在这里选：

| 档位 | 行为 |
|---|---|
| **自动**（默认） | 探到显卡就先试 `lib/` 那套，**起不来自动换 CPU 那套** |
| **只用 CPU** | 只用 CPU 版。最稳，也最慢。显卡不被支持、或者想省显存时选它 |
| **只用 GPU** | 只认 `lib/` 那套。**它起不来就不会自动落回 CPU** |

那个框里还会显示：

- `lib/` 和 `lib_cpu/` 各自的现状（**是哪一套**、多大、什么时候换的）
- **这一次启动实际用的是哪套**
- 如果你刚改了还没重启，它会明说「存的是 X，本次启动用的还是旧的」

> ⚠ **改完要重启软件才生效。** 两套框架是两套 DLL，程序一启动就把其中一套
> 加载进内存了，**运行中换不掉**。那个框里写得很明白，不会让你以为已经切过去了。

### 7.8 重编本地框架

**在哪**：菜单 **接口 → 重编本地框架…**（`Ctrl+B`）。

**什么时候用它**：包里那份 GPU 框架只对**一种卡**有效 —— CUDA 那份是按
**sm_120（RTX 50 系）** 编的。你的卡要不是 50 系（比如 30 / 40 系），
加载模型时会报 `no kernel image` 之类的错；要是 A 卡 / Intel 卡，
那份根本用不了。**这两种情况都来这个框，在你自己这台机器上给你的卡编一份。**

**为什么不用装 VS / CUDA / Vulkan SDK**：包里 `编译环境/` 已经带了一整套
（精简过的 MSVC + Windows SDK + CUDA + Vulkan SDK + 便携 Python + 源码包）。
**全程离线**，不需要联网。

#### 先选挡位：NVIDIA 还是 AMD

框里第一行是**编译挡位**，就两挡：

| 挡位 | 走哪条路 | 特点 |
|---|---|---|
| **NVIDIA 显卡（CUDA）** | CUDA | 产物**绑死一个架构号**（就是下面那个 sm）——**一张卡编一份** |
| **AMD 显卡（Vulkan）** | Vulkan | 产物是 SPIR-V，**与显卡型号无关** ——**编一次，AMD / Intel / 核显都能吃** |

⚠ **切到 AMD 挡位时，那个 sm 框会自动灰掉** —— 那条路不需要架构号。
（留着它能填反而有害：见了架构号，编译器会去找 CUDA 工具链。）

**怎么用**

1. 打开框，先确认挡位选对了：
   - **NVIDIA 挡位** —— 它会自动探测你这张卡，把卡名和架构号填好
     ```
     编译目标：sm [89]     本机显卡：NVIDIA GeForce RTX 4060
     ```
     （你自己改过那个数字之后，就不会再被探测值覆盖）
   - **AMD 挡位** —— 不用管架构号，目标那行会显示「编译目标：与显卡型号无关」
2. 点 **开始编译** —— **几十分钟**，日志会实时滚
3. 编完**自动换装**，然后提示你重启
4. 重启 → 吃上 GPU

#### 常见显卡的 sm 值（速查）

> ⚠ **这张表只对 NVIDIA 挡位有效。** AMD 挡位（Vulkan）压根不要架构号 ——
> 那正是它"一份通吃"的底气。

那个 **`编译目标 sm [__]`** 里的数字，就是显卡的 **compute capability**。
软件**会自动探测填好**，所以正常情况下你不用管它 —— 这张表是给你
"想手动改"或者"想知道为什么是这个数"的时候看的。

| 显卡 | 架构 | sm |
|---|---|---|
| **RTX 50 系**（5050 / 5060 / 5070 / 5080 / 5090，含笔记本版） | Blackwell | **120** |
| **RTX 40 系**（4060 / 4070 / 4080 / 4090，含笔记本版） | Ada | **89** |
| **RTX 30 系**（3060 / 3070 / 3080 / 3090，含笔记本版） | Ampere | **86** |
| **RTX 20 系、GTX 16 系**（2060 / 2070 / 2080、1650 / 1660） | Turing | **75** |
| **GTX 10 系**（1050 / 1060 / 1070 / 1080） | Pascal | **61** |
| 专业卡 RTX A2000 – A6000 | Ampere | 86 |
| 专业卡 RTX 4000 / 5000 / 6000 Ada | Ada | 89 |
| 数据中心 A100 | Ampere | 80 |
| 数据中心 A10 / A40 | Ampere | 86 |
| 数据中心 L4 / L40 | Ada | 89 |
| 数据中心 H100 / H200 | Hopper | 90 |
| 数据中心 B100 / B200 | Blackwell | 100 |

**几条要注意的**

- ⚠ **不同架构不能通用。** 一份产物只认一个 sm 值 —— 给 4060（89）编的那份，
  拿到 4090（89）能用，拿到 3080（86）就不行。**一张卡编一份。**
- ⚠ **别只看系列名。** 有个著名的例外：**RTX 2050 / MX570 其实是 Ampere（86）**，
  不是 Turing —— 虽然它挂着"20 系"的名字。
- ⚠ **笔记本版和台式机版同型号，通常是同一个 sm 值**（架构一样）。
- 💡 **拿不准就别改。** 软件探测出来的那个数就是最准的 —— 它是直接问显卡驱动要的。
  真想自己查，NVIDIA 官方的 CUDA GPU 支持列表（`developer.nvidia.com/cuda-gpus`）
  是最权威的。
- 💡 **一台机器有两张不同代的卡** → 一次只能编一种架构。挑你要用的那张编，
  想两张都用就编两次（每次装上去一份）。

**中途想停**：点 `停止`（会杀掉整棵编译进程树）。

**编出来的东西放在哪**

```
编译产物（wheel）      编译环境/_编译产物/
现在这套 DLL           依赖库/llama_cpp/lib/
旧的那几套（备份）      依赖库/llama_cpp/lib_旧_<时间戳>/
换装失败留下的现场      依赖库/llama_cpp/lib_新编/
```

**旧备份是唯一的退路**，所以换装只敢改名、不敢删。框里那个
**`还原上一份`** 下拉 + `还原` 按钮，就是靠它。

> ⚠ **换装之前会先"试加载"一次**（开一个干净子进程 `import` 一下）。
> 通不过就**一个字节都不动**，现在这份继续用 —— 不会把你搞成
> "新的是坏的、旧的也没了"。
>
> ⚠ **换完必须重启**：正在跑的这个进程用的是已经加载进内存的旧 DLL。
>
> ⚠ **必须在那张卡的机器上编。** 架构号是绑死进产物里的，
> 在 A 机器上给 B 机器的卡编不出来。

**全部在程序旁边的 `酒馆数据/`**（状态栏左下角显示完整路径，鼠标悬停有说明）。

## 九、我的显卡能不能用 GPU

**包里那份** GPU 框架是按 **CUDA / sm_120（RTX 50 系）** 编的 —— 所以：

| 你的显卡 | 开箱能用 GPU 吗 | 怎么办 |
|---|---|---|
| **RTX 50 系**（sm_120） | ✅ **能**，什么都不用做 | —— |
| **其他 NVIDIA 卡**（30 / 40 系等） | ❌ 会报 `no kernel image` | 「重编本地框架」选 **NVIDIA 挡位**编一份，架构号会自动填好 |
| **AMD 显卡（Radeon）** | ❌ 包里那份是 CUDA 的，A 卡用不了 | 「重编本地框架」选 **AMD 挡位**编一份 |
| **Intel 显卡 / 核显** | ❌ | 也选 **AMD 挡位** —— Vulkan 不分厂家，一份通吃 |
| **没有独显 / 显卡不被支持** | ❌ | 用 CPU 版（界面会自动切过去，不用管） |

**两挡的区别，一句话**：

- **NVIDIA 挡位**编出来的**只认一个架构** —— 一张卡编一份；
- **AMD 挡位**编出来的是 Vulkan，**与显卡型号无关** —— 编一次，AMD / Intel / 核显都能吃。

**判据不是"有没有驱动"**，而是"卡在不在 + 架构对不对"。N 卡那边只要驱动正常
（有 N 卡的机器基本都有），**编译器就能自动认出你的卡**，架构号不用你操心；
A 卡 / Intel 那边连架构号都不用管。

另外：**用 CPU 版也能正常聊天**，只是慢。用哪套的切换见
[7.7 模型框架配置](#77-模型框架配置)；**各型号 N 卡对应的 sm 值**见
[7.8 重编本地框架](#78-重编本地框架) 里的速查表（不过软件会自动填，一般不用你查）。

## 十、常见问题

### Q：界面上写着「引擎状态：没装上」怎么办？

按这个顺序查：

1. **`依赖库/llama_cpp` 是不是被杀毒软件隔离了？**（最常见的原因）
2. **整个文件夹拷全了吗？** 只拷 exe 是跑不起来的 —— `依赖库/` 必须同级。
3. 上面两条都没问题 → 去 **接口 → 模型框架配置…** 看看两套框架的现状那一栏报了什么。

### Q：本地模型加载时报 `no kernel image` 之类的错？

包里的那份 CUDA 框架不是给你这张卡编的。三条路：

1. 去「接口配置」把那套的 **GPU 层数改成 0**（同一个框架内退回 CPU）
2. 去「模型框架配置」**切成 CPU 版**
3. 想真吃上 GPU → 去「重编本地框架」**选 NVIDIA 挡位自己编一份**（推荐）

### Q：我是 AMD（Radeon）显卡，能用 GPU 吗？

**能，但要自己编一份。**

包里那份是 CUDA 的，A 卡用不了 —— A 卡该走的是 **Vulkan**：

1. 菜单 **接口 → 重编本地框架…**
2. **编译挡位选「AMD 显卡（Vulkan）」** —— 这时那个 sm 框会自动灰掉（那条路不要架构号）
3. 点 **开始编译**，等几十分钟，编完**重启**

**Vulkan 那份是"一份通吃"的** —— 编一次，AMD / Intel / 核显都能用，
不像 CUDA 那样得一张卡编一份。

⚠ **Intel 显卡 / 核显也走这一挡** —— Vulkan 不分厂家。

### Q：模型下载卡住了 / 想取消？

- 「取消」是置了个旗，**真正的生效点在这次下载回来之后**，所以点完可能还会
  再跑一小会儿，属正常。
- 断了也不要紧：**断点续传**，下次接着下。
- 下不完的半截文件不会被当成模型，不会被误挪进模型目录。

### Q：首字好慢，而且点了「停止」没反应？

本地模型在**吃下整段提示词（prefill）的那段时间里是没法中断的** ——
这是 llama.cpp 的 Python 绑定本身的限制，不是这个软件的问题。
提示词越长，首字越慢、打断越钝。

**缓解办法**：在「上下文」里把上下文条数或字数上限调小一点。

### Q：聊天时中间那条接口下拉是干嘛的？

它**只影响你当前这一段会话**。换个会话就是另一套接口 ——
可以一段会话用本地模型、另一段用在线 API。

### Q：杀毒软件报毒 / 把东西删了？

自己打包的程序（PyInstaller 的 exe、以及编译器的外壳程序）**没有数字签名**，
个别杀毒软件会多看两眼。如果被隔离：

1. 把整个软件目录加进杀软的**排除 / 白名单**
2. 恢复被隔离的文件
3. 重新打开软件，看「引擎状态」那行

（被隔离最多的通常是 `依赖库/llama_cpp/` 下面那几个 DLL。）

### Q：能放到中文目录、桌面、U 盘吗？

**能。** 中文路径（包括中文用户名）都没问题。
U 盘也可以，但下载模型和编译最好放在本地磁盘上做。

### Q：数据想搬家 / 备份？

把 `酒馆数据/` 整个拷走就是完整备份。换机器时连同程序目录一起拷即可。

## 十一、第三方组件

这个软件用到了下面这些：

| 组件 | 用途 | 随包带什么 |
|---|---|---|
| **llama.cpp** / **llama-cpp-python** | 本地 GGUF 模型推理 | 编好的框架（CUDA / CPU） |
| **PySide6**（Qt for Python） | 界面 | `依赖库/` |
| **NVIDIA CUDA 运行时**（cudart / cublas） | N 卡的 GPU 加速 | `依赖库/llama_cpp/lib/` |
| **MSVC + Windows SDK**（精简版） | 「重编本地框架」用的编译器 | `编译环境/` |
| **Vulkan SDK**（精简版，约 33 MB） | 「重编本地框架」的 **AMD 挡位**用的（`glslc` + 头文件 + `vulkan-1.lib`） | `编译环境/VulkanSDK/` |
| 其他 Python 包 | —— | 见 `依赖库/` 目录 |

> ⚠ **关于随包分发的注意**：包里的 `编译环境/` 带了一份精简的 **MSVC 工具链**
> 和 **CUDA 工具包**，这两者的授权条款对"整套转发"是有限制的 —— 自用没问题，
> **公开分发这个包之前建议先自己确认一遍许可**。
> （**Vulkan SDK 那部分不受这条影响**：它主要按 **MIT / Apache-2.0** 授权，随包带没问题。）
